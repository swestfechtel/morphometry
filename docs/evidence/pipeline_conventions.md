# Data-layout traps, test fixtures, batch exception handling

*Moved verbatim from `CLAUDE.md` on 2026-11-12 when that file was cut below its size limit; `CLAUDE.md` keeps a summary and links here. Nothing below was rewritten.*

- **Data-layout trap in the Augsburg reader-study directory, which silently changes numbers.** Each `reader_study_augsburg/<patient>/` holds **two** segmentations per region: `<region>_seg.nii.gz` (dated Nov 2024) and `<region>_seg_test.nii.gz` (Jul 2025). **Only the `_test` files are production**: `scripts/process_augsburg_reader_study.py:26-30` and `tests/conftest.py:64` both read `*_seg_test.nii.gz`, and the `_test` file is the one that matches `preprocessed/<patient>/<region>_seg.nii.gz` — so the identically-named file in the reader-study folder is the *stale* one, which is the opposite of what the names suggest. Reading the wrong one does not error, it just gives different answers: over the 100 reader-study halves the Lee `a` comes out min **1.2226**, median 1.4944, **0 below 1.0** from `hip_seg.nii.gz` against min **0.7684**, median 1.5529, **1 below 1.0** from `hip_seg_test.nii.gz` — i.e. `PA000346`, the half every Lee bullet above is about, disappears entirely. A probe of mine read the stale file and produced a confident contradiction of a correct result before the cause was found. Always take the reader-study path from `tests/data_paths.py` or the script, never by globbing for `*_seg.nii.gz`. **And the same class of hazard exists in `preprocessed/` itself, with a different suffix**: `PA000031/` holds `knee_seg.nii.gz` (14,615 B, Jul 2025) *and* `knee_seg_clean.nii.gz` (191,990 B, Feb 2025), plus the matching `hip_seg_clean.nii.gz` beside `hip_seg.nii.gz` — it is the only case with them, so `find -name 'knee_seg*.nii.gz'` returns **953** files where `-name 'knee_seg.nii.gz'` returns 952, and a `knee_seg*` glob would silently measure that one case **twice**, once on a non-production file. Its eight half-measurements are 25.08-43.74 voxels either way, i.e. deep in the bulk, so nothing in this file is affected by it — but the trap is live for the next survey. Both cohorts: match the production filename exactly, never a prefix.
- Data-locating fixtures in `tests/conftest.py` **skip** when sample data is absent. Markers: `needs_augsburg`, `needs_augsburg_reader_study`, `needs_nako`, `needs_ct`, `needs_dfg_knees`, `stochastic`. Override data paths with `MORPH_AUGSBURG_PA000001` / `MORPH_AUGSBURG_READER_STUDY` / `MORPH_NAKO_SAMPLE_DIR` / `MORPH_CT_SAMPLE` / `MORPH_DFG_KNEES_DIR` / `MORPH_DFG_KNEES_CURRENT_DIR` (the current 113-scan label set, used only by `tests/characterization/test_cartilage_deformation.py`; `MORPH_DFG_KNEES_DIR` is the older set the knee goldens are pinned on). CT tests read large volumes over sshfs (~minutes) — run `pytest -m "not needs_ct"` for a fast loop. `data_paths._exists` treats an **unreachable** filesystem as absent: `Path.exists()` raises `OSError` rather than returning `False` on a dead mount, and because `data_paths` is imported by `conftest.py` that exception surfaced during *collection* and took the whole suite down instead of skipping the 22 `needs_ct` tests it should have. The sshfs mount holding the CT sample goes stale whenever the connection drops, so this is the normal case, not an edge one. The `dfg_knees` fixtures (`dfg_knees_dir`, `dfg_knee_file`, `dfg_knee`) load a knee the way the knee scripts do — LPI, **no** `remove_outliers()` — unlike the generic `_load_seg`, so the knee goldens pin what production produces; they replaced a local skip with a `MORPH_DFG_KNEES_SAMPLE` override.
- Failures inside batch scripts and `compute_torsion.py` are caught per-measurement and written out as `np.nan` so a single bad patient does not abort a cohort run. Keep this behavior when extending those scripts. **The exact tuple differs per file, and the rest of this document simplifies it — corrected 2026-11-06 after being checked per file.** `morphometry/docker/compute_torsion.py` catches `(RuntimeError, AssertionError, ValueError)` (6 sites), and that is the tuple quoted elsewhere here. But `scripts/process_augsburg_{reader_study,large_dataset}.py` catch **`(ValueError, IndexError, RuntimeError)`** (16 sites each) — so on the Augsburg path an **`IndexError` is caught** and an **`AssertionError` aborts the run**, which is the *opposite* of what the simplified tuple implies in both directions. `scripts/process_nako{,_large}.py` are different again and the most forgiving: every measurement sits under a bare `except Exception` (10 and 14 sites), so nothing escapes there at all. `scripts/process_nmdid.py` wraps its QC in its own `try` and logs a warning. **Read the file before relying on a tuple**: the five earlier mentions in this document are written as "the batch scripts" and are accurate only for `compute_torsion.py`. The practical consequences are unchanged wherever a function raises `ValueError` (caught everywhere) — which is every guard this document discusses — so no decision recorded here is invalidated; what changes is the *reason* those guards are safe on the Augsburg path.
