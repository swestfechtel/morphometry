# Batch scripts — full reference

The detailed CLI and output reference for `scripts/`. *Moved verbatim from `CLAUDE.md` on 2026-11-12 when that file was cut below its size limit; `CLAUDE.md` keeps a summary and links here. Nothing below was rewritten.*

- `scripts/` — one-off batch processing scripts (`process_augsburg_*.py`, `process_nako*.py`, `combine_series.py`, etc.). Each script is self-contained and typically prepends `sys.path.append('/home/simon/Work/morphometry')` and hard-codes absolute data paths (e.g. `/home/simon/Data/...`); update paths when running elsewhere. `process_augsburg_reader_study.py` and `process_augsburg_large_dataset.py` write their xlsx with a `qc_flags` column appended after the measurement columns by `add_qc_flags` (the Murphy neck-base flags of that leg; Side is the *patient* side, so the image-left half lands on 'right'). A few are proper `argparse` CLIs — e.g. `compute_knee_cartilage_thickness.py -i <seg.nii.gz ...|dir> [--femur-label 3 --tibia-label 4 --tibia-bone-label 2 --femur-bone-label 1 --laterality-table lat.csv -o summary.csv --dump-json maps.json --visualize both --screenshot <dir> --html <dir>]` computes per-subregion knee cartilage thickness and optionally renders the 3D segment/heatmap views (via `plot_knee_segments`/`plot_knee_thickness`) as PNGs (`--screenshot`) and/or self-contained interactive HTML (`--html`). There is **no `--method`** any more (it is accepted and rejected with an explanation, so an old command line fails loudly). After the existing columns the CSV carries the paper's area-weighted statistics — `aMe_mm` (ThC.cAB.aMe, the number to quote), `tab_aMe_mm`, `aMax_mm`, `aMav_mm`, `aSD_mm`, `aMin_mm`, `aMiv_mm`, `tab_area_mm2`, `cab_area_mm2`, `denuded_fraction` — while `mean_mm`/`std_mm`/`min_mm`/`max_mm`/`n_points` stay the unweighted statistics of the per-position map (a "point" is now an in-plane grid cell of the knee's shared frame, not a voxel column). The JSON gains `statistics` and `frames` beside the per-bone maps. `-i` accepts multiple files and/or directories (searched recursively for `*.nii`/`*.nii.gz`); multiple inputs batch into one combined CSV (leading `subject` column) + one combined JSON (keyed by subject). All visualisation files land flat in the `--screenshot`/`--html` dirs named `<subject>_knee_<view>.<ext>`. Output paths ending without an extension are treated as directories (`summary.csv`/`thickness.json` written inside). The CSV's last column `qc_flags` (also a per-subject `qc_flags` key in the JSON) carries `cartilage.knee.scan_qc_flags`: `;`-separated `name:value` flags in `process_nmdid.py`'s format — `non_lpi_orientation:<codes>` (scan not LPI after reorientation), `tibia_transfer_far:<fraction>` and `femur_transfer_far:<fraction>` (that bone's `transfer_qc` far fraction above `TRANSFER_MAX_FAR_FRACTION`); empty = clean. Flagged scans are measured and written as usual; a scan for which both bones fail, or whose processing raises (with its orientation flag if it loaded), keeps one placeholder row (empty `bone`/`subregion`, NaN stats) so it and its flags stay visible. `process_nmdid.py -i <seg.nii.gz ...|dir> -o <dir> [--shard I/N --workers N --cohort-status cohort_status.csv --verdict usable review --limit N --overwrite --merge]` batches the whole-leg **CT** measurements (femoral torsion/Murphy, tibial torsion, CCD, femur & tibia length, femoral offset, mechanical axis deviation, HKA, center-edge angle, acetabular version) over the NMDID cohort, one CSV row per (case, image side). Built for SLURM: `--shard` (or `SLURM_ARRAY_TASK_ID` / `SLURM_ARRAY_TASK_COUNT`, see `process_nmdid.sbatch`) strides the cohort across job-array tasks that each fan out over their node's CPUs into their own `shard_XXX.csv`; `--merge` concatenates them. Rows are flushed per case, so an interrupted run resumes. Because these are whole-*body* scans, `clean_leg` drops the mislabelled arm bones (non-pelvis label components lying entirely above the hip bone) and the spine/rib fragments in the pelvis label; segmentations that are damaged in ways it will not silently repair are reported in a `qc_flags` column instead. That `qc_flags` column also carries the Murphy femoral-neck flags of `murphy_neck_base_qc` (`;`-joined onto the segmentation-integrity ones), so a row whose femoral torsion rests on a degenerate neck is marked while keeping its value.
 - `process_nako_large.py --chunk N [--input-root <dir> --output-dir <dir> --workers N --overwrite]` measures one chunk of the NaKo cohort (`<input-root>/chunk_N_segmentations`, `.nii.gz` only — the chunk dirs also hold three nnU-Net json files) into `results_chunk_N.csv`, in the original cohort-table layout (one row per Patient and *patient* Side; image-left half = patient right) with a `qc_flags` column appended last (that hip's Murphy neck-base flags, see the Murphy bullet below; empty = sound, and `AT_murphy` is written either way), plus `results_chunk_N.meta.json` (git commit, dirty flag, date, args). Each finished case is flushed to `results_chunk_N.partial.csv`, so a killed task resumes on resubmission (a case torn mid-write, or a partial with no complete row, is dropped and recomputed). A case that cannot be loaded is not flushed but retried once at the end of the run, then written as all-NaN rows; more than `--max-load-fail-frac` (0.01) load failures in a chunk fail the run without finalising (a broken mount, not bad files). A worker that dies hard raises `BrokenProcessPool` rather than hanging and saves the cases in flight to `results_chunk_N.suspects.json`; the next run measures each suspect alone first and writes one that still kills its worker as all-NaN rows. Both kinds of NaN case are listed in the meta file (`load_failed`, `crashed`). When every case is in, the rows are sorted into `results_chunk_N.csv` and the partial file removed. A finished chunk CSV is refused without `--overwrite` (which starts the chunk afresh). `--output-dir <dir> --merge [--expected-chunks 20]` concatenates the chunks in numeric order into `<dir>/results.csv`, refusing missing, unfinished or out-of-range chunks and duplicate (Patient, Side) rows. `process_nako_large.sbatch` is the SLURM array (tasks 0-19, one chunk each, 32 CPUs) writing to a fresh `~/Data/nako/rerun_<short sha>`; it refuses a dirty checkout, and the checkout must not change until the array has finished. Acetabular anteversion now runs with `isotropic=True` like every other NaKo measurement (before: `isotropic=False`, the consensus head-centre fit). Cohort tables from before this change also hold empty rows named after the json files (`dataset`, `plans`, `predict_from_raw_data_args`); the cohort is 30,407 cases.
 - `analyse_thinnest_point_flexion.py -i <dir> [--tibia-bone-label 2 --femur-bone-label 1 -o <dir> --screenshot/--html <dir> --visualize]` groups `K<subject>_<angle>_<load>.nii.gz` segmentations by `(subject, load)` and tests whether the thinnest point migrates posteriorly with flexion — measured as the thinnest point's arc-length fraction along the femoral subchondral bone area in the sagittal cross-section of the **femoral frame** through it (`femur_regions.articular_arc_fraction`; 0 = anterior/trochlea, 1 = posterior condyle, clamped to the outermost cross-section for a point up to `max_outside_mm` (1 mm) past the condyle's medial-lateral edge — without any clamp 16 of 288 cohort rows were NaN, because a cut plane through the very edge of the mesh intersects nothing; further out than that the cross-section is a near-degenerate sliver whose fraction is not comparable, so it stays NaN), which is built from the femur alone and so does not move with the knee's pose. It is only *approximately* flexion-invariant, though: the arc is normalised over a contour whose anterior end is the edge of the labelled trochlear cartilage, which step 3 already records as not flexion-reproducible. Measured on fixed anatomical landmarks (each femoral region's area-weighted tAB centroid), the arc fraction wobbles across the four flexion scans of one knee with a within-series SD of 0.017-0.065 per region (max 0.19) — 15-20% of the effect size the analysis looks for (median slope 0.0039/deg × 90° ≈ 0.35) — summarised per series (Spearman ρ + slope) and cohort-wide (binomial sign test). `detail.csv`'s point columns are `thin_u`/`thin_v`, the thinnest point's cell in the knee's shared in-plane frame (they were image indices `thin_x`/`thin_y` before), and there is no `--method` (see the thickness script). **Every earlier run of this script is superseded**: the thickness definition, the map keys, the `ap_fraction` coordinate, the joint-facing-sheet selection and the thinnest-point refinement fix all changed. The per-compartment sign tests in particular are **not robust to the search restrictions**: the always-on full-window rule removes a median 27.3% of the candidate cells and moves the chosen cell in 279 of 279 compartment results (median |Δ arc| 0.233, max 1.0), and switching it off reorders which compartment looks most significant (whole knee 20/24, patient-left 21/24, patient-right 18/24 without it, against 20/24, 22/24 and 21/24 with it). Quote the per-compartment p-values only with that caveat, or not at all. At the *same* point the old (image-space) and new (femoral-frame) `ap_fraction` formulas differ by a median 0.079 over the 89 clean scans where both are defined (p90 0.670, max 0.990; per angle, median |Δ| 0.071 / 0.055 / 0.080 / 0.187 at 0/30/60/90°), and their Spearman correlation is only 0.54 — they are not interchangeable. Everything is done per **compartment** — `both` (whole knee), `left`, `right`: `detail.csv` is long format (exactly one row per parsed scan × compartment, `compartment` column after `angle`), series and `summary.csv` (insufficient series kept with NaN stats) are keyed by `(subject, load, compartment)`, and the sign test is reported separately per compartment (separate, uncorrected tests; the two loads of one subject are not independent). 'left'/'right' is the PATIENT side (from the NIfTI header after LPI reorientation), not medial/lateral: patient-left is medial in a right knee and lateral in a left knee, so a per-side sign test reads as medial or lateral only if every knee in the cohort is the same side. A compartment whose search fails becomes NaN for that scan (stderr warning) without dropping the other compartments; a scan whose thickness pipeline fails is written as NaN for all three. `detail.csv`'s last column `qc_flags` holds the scan's `scan_qc_flags` (same flags as the thickness script; a scan that loads but then fails keeps its orientation flag), and `summary.csv`'s last column `qc_flagged_angles` lists the `;`-joined angles of the series' flagged scans; flagged scans still enter the statistics. Visualisations draw one arrow per compartment in a single scene.
 - `report_knee_cartilage_cohort.py -i <seg.nii.gz ...|dir> -o <dir> [--workers N --include-flagged --exclude SCAN ... --min-angles 3]` regenerates the `dfg_knees` cohort tables this file and `docs/wirth_eckstein_2008_plan.md` quote — the Table I analogue (tibial region shares per plate), the Table II analogue (femoral thirds per condyle), tAB/cAB areas and the denuded fraction per subregion, the thickness statistics per subregion, the whole-bone `aMe` per flexion angle, the loaded-vs-unloaded and across-flexion spreads, and a QC summary. Writes `scan_metrics.csv` (long: scan × bone × region, plus the `plate_*` / `cf_*` / `whole` aggregates), `scan_geometry.csv` (long: scan × geometry/QC scalar), `cohort_summary.csv` (long: one row per statistic, `table, scope, region, unit, n, mean, sd, min, max, p50, p90, paper`; carries no timings, so two runs that computed the same numbers give the same file whatever `--workers` was), a human-readable `report.md` and `report.meta.json` (commit, dirty flag, branch, host, date, args, inputs, scan counts, per-bone timings — the provenance a "re-derivable" table needs). An aggregate row's `aMe`/`cMe`/`bMe`/`tab_aMe` are **exact** (each direction weighted by its own area — cAB for `cMe`, AC for `bMe`) and so are `aMin`/`aMax`/`tab_aMin` (min/max over the parts, so one denuded triangle makes `tab_aMin` exactly 0); its `aSD`/`aMav`/`aMiv`/`tab_aSD` are area-weighted means of the subregion values and under-state the union's spread — `report.md` says so above the table. Failures are per scan and per bone, and every scan keeps its `scan_qc_flags` string in a `qc_flags` column; by default the statistics cover the scans that measured **and** carry no QC flag (93 of the 96 `dfg_knees`), while `--include-flagged` / `--exclude` reproduce an older set (the 94-scan tibial table: `--include-flagged --exclude K7_90_belastet K11_90_belastet`). The reproducibility sections are **spread, not precision** — the loaded/unloaded and flexion scans are different acquisitions of a repositioned knee, not repeats, so they are not comparable with the paper's 19-84 µm test-retest rms SD — and the pooled rows cover the 20 subregions only, never the aggregates. Region keys are patient-side and the knees' laterality is unrecorded, so the paper's medial/lateral values are printed in their own table and their own summary rows, never paired with ours.
 - `analyse_cartilage_deformation.py -i <seg.nii.gz ...|dir> -o <dir> [--workers N --knees K1 K7 ... --include-flagged --exclude SCAN ... --laterality-table CSV --grid-mm 1.0 --neighbourhood-mm 3.0 --edge-margin-mm 2.0 --max-registration-rms 1.0 --no-cache --femur-label 3 --tibia-label 4 --femur-bone-label 1 --tibia-bone-label 2]` maps where knee cartilage changes thickness between configurations: per knee, each of the seven configurations `(0|60|90 unloaded, 0|30|60|90 loaded)` against the knee's **unloaded 30°** scan (Δ = configuration − reference, mm, negative = thinner). Input is the **current** `dfg_knees` label set, `/home/simon/Downloads/dfg_knees_segmentations/dfg_knees/segmentations` (113 scans, 15 knees; seven knees — K7, K8, K10, K11, K14, K15, K25 — have no 90° loaded scan, status `missing`); never mix in `/home/simon/Data/dfg_knees/monai_segmentations/labels/{original,final}`, the older set the knee goldens and `report_knee_cartilage_cohort.py`'s quoted tables still use — **re-pinning the knee goldens and re-deriving those tables on the current set is open follow-up work**. Three stages: per scan (both bones' Wirth & Eckstein subdivision + per-triangle thickness, process pool, cached under `<out>/cache/<scan>.pkl` ~60 MB each, reused only for the same clean commit, file size/mtime and labels — so any new commit re-measures), per knee (bone registration, Δ maps, hotspots, figures) and cohort. Writes `subregion_delta.csv` (knee × comparison × bone × subregion: `aMe_ref_mm`, `aMe_mm`, `delta_mm`, `delta_pct`, `status` ok/missing/failed, `qc_flags`), `hotspots.csv` (knee × comparison × bone × compartment `both/left/right`: map and world position, subregion, smoothed and raw Δ, `edge_distance_mm`, `fallback`), `registration.csv` (`rms_mm`, `median_mm`, `p95_mm`, `n_points`, `iterations`, `converged`, `rotation_change_deg`, `dropped_fraction`, `reference_unmapped_fraction` — the knee's covered reference tAB with no map coordinate, repeated per row — and its split by cause `reference_unmapped_{detour,no_crossing,no_profile_point,off_bone}`, `flagged`), `failures.csv`, `<knee>_{tibia,femur}_delta.png` (2×4 panels: the reference thickness, seven Δ maps, a grey "no scan" / "failed" panel, subregion borders and the whole-bone hotspot ✕), `{tibia,femur}_hotspots_cohort.png`, `cohort_summary.csv`, `report.md` (with an "Open caveats" section: hotspot crowding at the edge margin (left/right hotspots only), the scans whose cartilage labels hold enclosed cavities — counted per scan by `count_enclosed_cavities` — and the reference unmapped fraction) and `report.meta.json` (commit, dirty flag, args incl. `hotspot_edge_margin_mm`, inputs, counts, missing/failed/flagged lists). **Current full run** (`/home/simon/Data/dfg_knees/deformation_f53c02a`, 16 workers, 4 min 57 s wall measuring all 113 scans afresh (552f598 took 8 min 58 s, 0d993a3 5 min 19 s; df36e88, the same code bar the grid extent, gave byte-identical CSVs and report), about 2 min for the per-knee + cohort stages from cache; only the newest run keeps its `cache/`): 105 comparisons per bone — femur 98 ok / 7 missing / 0 failed, tibia 88 ok / 7 missing / 10 failed (all `ValueError: the two tibial plates overlap after hole filling`: K8's reference, hence its six comparisons, plus K3 0° loaded, K11 0° unloaded, K23 0° and 60° loaded), 0 QC-flagged, no comparison with failed maps but kept subregion Δ; every `subregion_delta.csv` value is identical to 0d993a3's. Per-subregion Wilcoxon p-values are **uncorrected** (10 subregions × 7 comparisons, on Δ in mm and again in %: 140 p-values per bone, 280 in all) and `report.md` says so; without `--laterality-table` every knee is pooled by patient-side key, i.e. assumed to be the same side, which the report states.
 - Two **analysis** scripts answer a specific backlog question rather than producing a cohort table, and each has a findings doc that is the thing to read; both measure the 50-patient Augsburg reader study and write only inside their `-o` directory. `analyse_reader_bias.py -o <dir> [--workers 12]` decomposes the CCD / Lee / Murphy disagreement with the two readers into an inter-reader scale, a shared-landmark component and a method-specific one (task #7 → `docs/augsburg_reader_bias.md`, **which carries a 2026-11-04 partial retraction**: task #2 showed the Lee−Murphy separation is anatomy, so the decomposition's "shared ≈ 0 / method-specific ±4.6°" split and its "the pipeline's gap is ~13° too wide" both invert — the readers' columns are what fail to reconcile, and no bias computed against them should be read as a pipeline defect until that is settled). `analyse_ccd_x_ratio.py -o <dir> [-i <root> --tables <dir> --workers 12 --skip-torsion]` sweeps the `x_ratio` slice-thickness factor over the MRI CCD, reporting the cohort mean, the reader-free within-patient left/right agreement, the bias against the readers and the size and slice span of the neck point cloud each factor selects, plus a torsion-invariance check at the two named factors (task #6 → `docs/ccd_x_ratio.md`). **Neither script picks a parameter**, and `analyse_ccd_x_ratio.py` says so in its own docstring: its criteria disagree and are computed on the same patients any choice would then be quoted against. Two more answer a question about the **whole-leg CT** cohort over sshfs and take `-i <dir|file ...> -o <dir>`: `survey_ct_spacing.py` reads **headers only** (so it covers the cohort in minutes) and reports each file's post-LPI in-plane spacing, whether the task #10 isotropy assert would refuse it and whether the reorientation achieves LPI — permuting the header zooms into the post-LPI axis order is the whole point, since the reorientation can move the slice axis *into* the plane, which is how `dfg_knees` comes to violate the precondition; `survey_ct_murphy_qc.py` loads each case properly (re-using `process_nmdid.py`'s own `load_case` / `split_legs`, so the legs are prepared exactly as production rows are) and reports the Murphy landmark failure reasons, the flag rate and the **axis-length distribution against the threshold**, because a rate alone cannot say whether a cohort straddles the gate or sits far from it (task #3 → `docs/ct_murphy_qc.md`, task #10 → the spacing survey quoted in Core data flow item 3).
